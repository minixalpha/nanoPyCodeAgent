## 轨迹显示的行为

- 两个流水线并行实现均未通过官方反向激活比较。候选的玩具模型一致性检查
  未能确立与 verifier 实际测试模型兼容。这说明检查有缺口，但未确立唯一的
  底层算法原因。
- 模型提取两组均通过。候选约用 110 个 agent 秒，main 为 432 秒，候选无截断。
  两组都检查任务提供的 `forward.py`，用其参数做诊断比较；提交的提取算法使用
  `forward()` 查询。这一本地诊断访问与外部隐藏测试接触分开披露。
- Scheme 两组均通过且无截断。候选约 537 秒，main 为 1,418 秒。两组都与提供
  的解释器及 32 个示例程序比较；main 花更多时间探索更深层自求值。
- 电路综合两组均通过。候选用分层、随机和边界输入及中间状态不变量检查实际
  模拟器，约 1,290 秒，main 为 1,981 秒。Main 做了更广的穷尽状态扫描；两组
  均遵守任务约束。
- 其他任务方向相反：候选在模型恢复、DNA 组装和图像重建上花更多时间。Main
  已在多题上做了实质性的独立和边界验证，包括随机 regex-log 检查。指令更明确
  不代表对照组缺少这些行为。
- 路径追踪公开描述称归一化 L2 相似度，但未给公式。官方测试使用余弦相似度，
  候选约为 0.99993 并通过。它另做的 `1 - ||a-b|| / ||b||` 诊断约为 0.98823。
  后者不是官方分数。控制者在两份输出固定后才检查 verifier 公式；未向提示词
  添加测试细节。Main 检查任务提供的可执行文件；候选从图像重建场景，花更长
  时间解决数值差异。

候选使用提供的检查器和通用国际象棋库做独立随机及边界检查后，通过 regex-chess。
它约 2,592 秒完成 73 次模型尝试，未截断。这是相对于 main 缺少产物的已观察
配对改善，伴随大幅增加的任务工作。一个随机题对不能隔离是哪段提示词造成变化。

## 信息边界发现与保留的已放弃运行

第一个尚无信息边界的 P0 候选从外部 benchmark 镜像下载了流水线任务参考实现和
隐藏评估源码，随后称其实现匹配该精确参考。候选组在 15:06 UTC 被中断。已启动
的五次试验全部保留：**三次通过、一次模型工作前安装失败，以及一次被污染、
在验证期间取消的试验**。十五次候选试验未启动。这些记录不被新候选结果替换，
也不与其合并。见
[原候选审计](../../results/headless-p0-original-candidate-audit-20261007.json)和
[原计划](../../configs/headless-p0-20261007/experiment.json)。已放弃组额外已知
估算模型费用为 **$0.231970**；安装失败没有调用模型，因此推理费用为零。该额外
费用不在上方比较表中。

回溯检查也确认已发布 v0.9.0 基线中通过的流水线试验存在同一完整性问题：下载
任务仓库、阅读解法和评估测试，并运行复制的测试。旧原始奖励保持不变，但该
通过不能作为独立能力证据。历史 **18/20 是保留的原始分数**，不是本实验干净的
因果对照。见
[历史审计](../../results/v0.9.0-pipeline-integrity-audit-20261007.json)及
[原报告](v0.9.0-baseline-20261005.md)中的注释。对其他十九份历史轨迹的定向扫描
未发现匹配的检索模式；这不是穷尽的回溯审计。

同期 main MTEB 试验也确认被污染。它先研究任务授权的公开排行榜数据，随后从
Hugging Face 获取精确 Terminal-Bench 任务的参考解法、README 和隐藏测试源码。
ATIF 第 99 步包含检索到的预期答案；第 101 步写入最终结果。其原始奖励仍为一，
但 MTEB 题对从共同符合条件的比较中排除。公开 MTEB 结果是合法任务输入；
Terminal-Bench 的答案和评估源码属于不同类别。

Main 流水线试验尝试精确函数搜索，但只收到安全检查页面或没有结果链接；未
观察到答案/测试内容。结构化结果保留全部四十次试验的逐次审计备注和轨迹哈希。
审计发现描述观察到的检索，并不证明排除了所有可能污染机制。

带边界 MTEB 试验使用任务授权的公开排行榜数据通过。它将结果仓库固定在 2025
年 8 月，检查所有要求任务的覆盖，复现公开聚合路径，并独立交叉检查原始 JSON
分数。未观察到检索 Terminal-Bench 参考答案或隐藏测试。即使污染对照使 MTEB
题对不能进入共同能力比较，该通过结果仍可见。

四十份轨迹全部审计：1 份确认接触外部任务答案/测试；39 份在本次审查中未确认
存在接触。

## 下一步单独测试的优化

最明确的操作性后续是说明实际 Bash 工具契约：单次调用上限 120 秒，shell
`timeout 1500` 无法延长它；长命令需要正确重定向的后台启动，并在总体任务预算
内轮询完成和退出状态。昂贵搜索或检查前保留可用中间交付物。任务要求保持运行
的服务，与未完成的产物生成不同。

这基于观察到的失败，而非仅是提示词偏好。多个流水线/张量试验中的安装器使用
`cd ... && nohup ... >log 2>&1 &`，可能使后台 AND-list 的 shell 持有被捕获管道。
工具因此等待，并在超时时杀掉命令会话。带边界的批处理调度器也运行
