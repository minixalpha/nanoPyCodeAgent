# 12 题 main 基线，2026-10-11

冻结的 main 运行时通过 **12 题中的 10 题（83.3%）**。另两题均进入官方断言，
因输出正确性失败。这十二次计分试验最终没有设置或 verifier 错误。这是一份
每题运行一次的新开发基线，不是与 PR #48 中提示词候选的比较。

失败暴露了两个具体的验证缺口：恢复前丢失原始证据，以及用共享未经证明假设的
参考实现验证自身实现。单纯增加自测数量无法解决这两个问题。

## 失败：数据库恢复破坏了自身证据

原始任务要求恢复全部十一条记录，**包括 WAL 变更**，并测试具体值。在 ATIF
第 5 步，agent 尚未复制数据库和 WAL 就运行了 `sqlite3 main.db`，同时只做了
640 字节的 WAL hexdump。第 7 步打开 `main.db-wal` 出现 `FileNotFoundError`；
第 9 步确认文件已消失。轨迹支持 SQLite 打开/关闭是原因，agent 也在第 11 步
认识到了这一点。

Agent 识别出 XOR 密钥 `0x42`，但仅有已捕获的前缀保留下来。它随后根据按字母
排序的水果名和 `value = id * 100` 模式猜测六条缺失记录，写入替代数据库/WAL
文件，并导出该重建结果。最终消息披露了丢失和猜测。

第 55 步验证 JSON 形状、十一条排序记录，以及 SQLite 与 JSON 一致。这些检查
比较的是由同一组猜测生成的两个产物，不能证明恢复了原始值。官方 verifier
发现第 1 行仍为 `100`，而已提交的 WAL 更新要求 `150`；
`test_recovered_data_completeness` 和 `test_wal_was_decrypted` 失败。因此，失败
涉及数据来源和保留，不是 JSON 语法或 verifier 依赖问题。

有益的 agent 改动是：打开有状态格式前保留完整原始输入，在副本上执行恢复，
并区分恢复出的事实和推断出的替代值。验证既要检查插入行数，也要检查已提交
的更新；不能把两个猜测产物相互一致当作原始数据已恢复的证据。

## 失败：模型转换共享了未经支持的假设

提供的 `model.py` 定义 784–16–16–10 ReLU 网络。Agent 提取权重，随后使用公开
MNIST 标签搜索预处理方案。第 51/53 步中，`(pixel / 255 - 0.5) / 0.5` 达到
92.07% 标签准确率，因此 agent 选择它而非简单的 `pixel / 255`。这为提高另一
目标——数字标签准确率——改变了所要求模型的可观察预测。

第 75/77/83/87 步中，C++ CLI 与单独编写的 Python 参考在 330 张图像上吻合，
包括小 margin 用例。两份实现都从生成的权重文件中读取同一推断归一化方式。
这有助于检测实现差异，却没有验证假设本身。Agent 最终消息承认预处理是推断的。
任务指令没有明确指定归一化方式，因此这是确实存在的不确定性，验证声明应
继续披露它。

官方 verifier 检查固定模型预测，在 MNIST 测试集前 50 张图像中发现 14 处不匹配。
十二题输出全部冻结后，独立诊断加载原始 float32 权重，用标准库 float64 算术
实现所提供的架构：

| 预处理 | 前 50 张图像中与官方预期不匹配的数量 |
| --- | ---: |
| `pixel / 255` | 0 |
| `(pixel / 255 - 0.1307) / 0.3081` | 10 |
| `(pixel / 255 - 0.5) / 0.5` | 14 |

最后一种方案复现了所有已报告的不匹配索引。这确认预处理足以解释观察到的
失败。诊断使用原始任务模型和公开 MNIST fixture；哈希及所有预测均记录在结果
JSON 中。它未修改提交、改变官方分数，也不构成另一次模型试验。

模型转换应保留源行为，并验证完整输入到输出契约。如果两个程序共享未经验证
的预处理选择，独立数值实现就不是独立判定参考。标签准确率不能替代行为等价。

## 安装与验证记账

最初的仅安装预检有五项成功、六项镜像拉取/启动错误和一次 APT 设置超时。第二次
有十一项成功和一次 uv 下载不完整。完整历史分别保留在
[第一份](../../configs/dev12-baseline-20261011/preflight-v1-evidence.json)和
[第二份](../../configs/dev12-baseline-20261011/preflight-v2-evidence.json)证据文件。
这八次预检失败与十二次计分试验分开记录。

任何模型启动前，计划 v3 为每题接受且仅接受一次成功的原生安装：第二次预检中
的十一项，以及第一次预检中 POV-Ray 的成功。可复用编排器验证其任务修订、源码
快照、已安装 wheel、引导状态、仅安装模式和产物哈希。没有合成成功结果。计划
修订期间运行时、提示词、任务、预算和队列均未改变。

该分支还新增了原始公开 Docker Hub 镜像的验证缓存。六次停滞的镜像下载通过
摘要校验的并行范围下载完成，并在未重建、未修改镜像的前提下导入。任务脚本、
包源和官方测试保持不变。十二项 verifier 依赖配置均仍为 **`not_configured`**：
从未将 agent 安装成功报告为 verifier 依赖预检成功。

PyTorch verifier 在依赖设置阶段达到 900 秒时限，超时一次；未修改的第二次尝试
完成并进入失败断言。其他 verifier 均在第一次尝试中完成。每次重试保留原生
单次时限和相同 agent 输出。十二项最终官方测试集全部执行，没有尚未解决、
需要从分母排除的 verifier 错误。

计分阶段从 **15:50:51 运行至 17:11:31 UTC**，经过约 **80.7 分钟**，不含之前
预检。跨并发试验累加的 agent 执行为 55.0 分钟，agent 安装为 39.9 分钟，验证为
34.7 分钟。这些累加值不是墙钟时长。日历任务单独安装花费 28.4 分钟，随后 agent
工作仅 30.2 秒。

记录的 token 估算费用合计 **$0.600974**，记账不完整：PyTorch 第 89 步遇到可恢复
的 `RemoteProtocolError`，无用量记录。合计仅覆盖已知用量，不是精确账单或完整
总额。记录用量为 9,362,395 个输入 token（9,171,328 缓存）和 407,188 个输出 token；
缺失用量不按零填补。该 agent 内部传输重试与禁止完整模型试验重试的策略独立。

## 审计边界与后续实验

在 17:09:54 UTC 观察到的检查点时，十二题输出已全部冻结，早于失败内容审计
开始。其轨迹哈希仍一致。最终检查还确认登记计划、提示词、任务文件、输入配置、
完整源码快照、wheel 摘要、原始镜像身份/registry 摘要，以及此前记录的已完成
结果哈希均一致。队列屏障和 verifier 重试限制由原生产物验证。十二次计分试验
完成后均未留下容器。

轨迹审查未发现检索外部 benchmark 解法或成功访问隐藏 verifier 内容的行为。
POV-Ray 使用官方上游归档；PyTorch 使用公开 MNIST 图像和标签，其中包括后来由
verifier 使用的样例。该重合已记录，不视为检索 benchmark 答案。多个 agent
搜索本地文件寻找参考，Git 和数据库 agent 读取了引导日志。这些观察不能证明
模型在训练中从未接触过该 benchmark。

数据库 agent 还在第 35 步读取了进程环境，使提供商凭据进入其本地轨迹。原始
日志必须保持私有，或在共享前脱敏。本报告及公开 JSON 包含派生观察和哈希，
不含原始环境值。防止凭据值进入工具观察，是另一项 agent 加固后续工作。

对于后续优化实验：

1. 完整保留这十二题。用两项失败开发输入保留和判定参考选择行为；十项通过
   保留为回归用例。
2. 要求为决定性需求提供证据：恢复任务看原始数据值，转换任务看源模型预测。
   追踪判定参考是否与实现共享假设或生成数据。
3. 增加受控开发变体，改变更新值或输入契约。保留官方基线，并标记变体为自定义
   测试。
4. 在相同预算下进行基线与候选的配对重复运行；测量任务分数、回归、无证据的
   完成声明和费用。单次本运行不能证明改进或估计方差。
5. 在候选方案和新的评估协议固定前，保持其余 55 题未打开。不要每看到一次开发
   结果就继续挑选新任务。

该分支的基础设施验证：**128 项 Harbor 测试通过**，包括镜像缓存和已接受预检的
来源测试。本基线未包含任何 agent 优化。
